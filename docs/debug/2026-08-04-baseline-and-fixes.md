## 已复现问题

### P0：课程在新标签页打开，但主程序仍控制旧页面

课表卡的 `goStudy` 点击成功后，21tb 在新标签页打开课程详情。原实现只检查旧页正文是否包含“课程学习/课程评估”等宽泛关键词，因此把课程中心误判为课程详情；后续类型识别、倒计时、评估、测试和验证全部在旧页面执行。

基线证据：点击后程序报告“真点击进入课程详情”，但 `page_state.url` 仍是课程中心 URL，且 `pageType=unknown`。

第二轮修复后已成功捕获并接管新标签页，课程 URL 正确；新的观察是课程前端 DOM 在初始等待窗口内尚未渲染，因此就绪检测需要轮询并输出选择器计数，而不能固定等待后单次判断。

后续实跑还出现过一次“课程 URL 正确但 title/body/DOM 持续为空”的间歇状态。恢复策略限定为仅在空白页时 reload 一次；非空但结构不符时不盲目刷新。

第五轮确认：课程页完整初始化后安装 `evaluateOnNewDocument` Hook 再 reload，会让 SPA 初始化失败，页面仅剩 `Ctrl M`。改为先等待课程页就绪，再在当前 document 安装 Hook；不刷新，通过重新点击章节创建使用新 Hook 的倒计时。

第六轮成功从 Vue `courseData/resourceDTOS` 识别出 8 个资源，并通过 `checkoutSection` 切换。第 1 章平台标记已完成；第 3 章实际观察到文档倒计时按约 32 倍下降。修正切换后的短暂旧文案误判：章节完成以 Vue `finish`、已观察到的倒计时消失或视频 ended 为依据，并验证 `curIndex` 已切到目标章节。

完整实跑中 8 个资源均逐章处理，章节 2、4、5、6、7、8 均观察到独立倒计时，切换后加速持续生效；章节 1、3 由平台异步返回的 `finish` 标记确认。随后课程评估成功填写并提交（28 个选择项、2 个文本项）。2026-08-06 复查课程中心，该课程显示“学习进度: 已完成”。

### P1：缺少多章节推进

原 `runAll()` 只处理当前页面上的单个视频或单个文档倒计时，然后立刻跳转课程评估，没有枚举章节、逐章切换和逐章完成确认。

### P1：主流程课后测试不是 AI 答题

原实现对选择题固定选择 D 或最后一项，并直接提交。AI 题库逻辑只存在于未接入的旧 userscript helper 中。

### P1：AI 供应商默认值与现有 Key 不匹配

首次连通测试按当前 helper 默认值请求智谱接口，返回 HTTP 401。本地 Git 历史表明项目曾声明兼容 DeepSeek/OpenAI-compatible API；当前 Key 采用 `sk-` 格式，因此改用可配置端点并按 DeepSeek 配置复测。配置名称暂时保留 `ZHIPU_*` 以兼容旧项目，后续文档标明其实际含义是通用 AI 配置。

使用 `deepseek-chat` 连通测试成功，模型对测试题返回合法选项 B。真实测试课程的结业条件仅包含“课程评估”，没有出现课后测试题，因此本轮只验证了真实接口调用和答题数据校验，没有为了测试而对其他未完成课程提交答卷。

### P1：评估提交后旧 iframe 失效导致流程中断

完整实跑中评估提交成功后，平台替换了课程 iframe。旧实现立即使用旧 frame 查找“课后测试”，触发 `Attempted to use detached Frame` 并退出。此时平台实际上已经记录课程完成，但程序未能进入最终验证。

修复后所有步骤点击会重新枚举当前 live frames，并对 iframe 替换/执行上下文销毁做有限次数重试；评估提交后的确认操作允许预期的 frame 替换。AI 调用完成后也会重新提取试卷并比较题目指纹，防止向已变化的试卷应用旧答案。

### P2：遗留主流程仍保留固定 D 答题代码

虽然命令入口已指向新流程，但文件中仍有一个不可达的 `runAllLegacy`，其中保留固定选择 D/最后一项和无条件 `all_done`。已整体移除该死代码，避免后续维护时误用或误认为仍存在答题兜底。

## 修复原则

1. 课程卡点击后必须捕获新标签页；只有课程详情 URL/DOM 校验通过才继续。
2. 章节学习采用“枚举章节 → 切换 → 识别视频/文档 → 等待完成 → 再推进”的显式循环。
3. 未观察到倒计时不能等同于完成；必须结合页面加载状态、完成文案或章节切换结果判断。
4. AI 请求失败、答案无效或题目未全部填写时禁止自动提交。
5. 只有回课表验证为完成时才输出 `all_done`，否则输出 `incomplete` 并以失败状态退出。
